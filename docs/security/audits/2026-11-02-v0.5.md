## Attack surface map (delta since v0.4.0)

- **B1, launch, macOS (new).** Finder hands files over as `open-file` events, which
  `instance-channel.ts:43` turns into `['--', path]`: files only, never switches. The installed `galeo`
  command is a copy of `gal` (unknown options refused, files after `--`). `CFBundleDocumentTypes` lists the
  document and data types as `Viewer`/`Alternate`; no URL scheme is registered.
- **B1, launch, Windows (new).** Explorer's "Open with" runs `"<galeo.exe>" -- "%1"` from both
  `galeo.document` and `Applications\galeo.exe` (`packaging/windows/associations.nsh`, generated and
  checked against the registry after a silent install in CI). `galeo.cmd` runs `"<galeo.exe>" %*` (L1). The
  portable build registers nothing.
- **B3, IPC.** No new channel. `app.installLauncher` and `app.uninstallLauncher` keep their input credit
  and now act on macOS and Windows. `AppInfo.appImage` became `commandLauncher` (a boolean).
- **B4, writes and deletes (new).** On macOS and Windows the launcher writes or removes one file:
  `~/.local/bin/galeo`, or `galeo.cmd` in `WindowsApps`, only while it carries galeo's mark. Saves on Windows
  retry the final rename on `EPERM`/`EBUSY` for about 200 ms.
- **B4, reads.** Find in all tabs reads as before and hands the bytes to the worker. Opening files now stats
  open tabs whose path differs only in case (`spelledAsOpen`).
- **B5 → B4, links.** `C:\…` and `C:/…` are now local paths (`hasScheme`), resolved and checked as `/…`
  paths are. UNC and device paths stay refused.
- **B7.** SR-05's list gains Windows and macOS types (L2).
- **B8.** Platforms workflow (`platforms.yml`), the release now gated on it, 10 packages checksummed and
  attested. Electron 45.2.1, katex 0.19.1. No new dependency.

## Per-SR verification (SRs the delta touches)

### SR-01 Hardened renderers — **PASS (unchanged)**

- `window/policy.ts`, `harden.ts` and the navigation and permission handlers are unchanged; the start-info
  switch now carries `commandLauncher`, a boolean. The same `hardenedWebPreferences` apply on every system.
- `tests/e2e/security/` passed on Linux; the Platforms workflow runs the same suite on macOS and Windows.

### SR-02/SR-03 Content is inert, safe rich renderers — **PASS (unchanged)**

- The only renderer changes are the CSV table's Cmd keys on macOS (`table-geometry.ts`, numbers only) and the
  launcher section's hint text (React text). A grep of `src/` for raw-HTML sinks finds only `host.ts`, as in
  v0.4. katex 0.19.1 is a patch release; the KaTeX options (`trust: false`, `maxExpand`) are unchanged.

### SR-04 Only safe URLs reach the OS — **PASS**

- `classifyLink` (`core/links/classify.ts:39`) still hands only `http:`, `https:` and `mailto:` to the OS.
- `hasScheme` (`shared/markdown/urls.ts:12`) no longer counts `X:\` or `X:/` as a scheme. Such an href now
  takes the local branch: decoded, checked against `NETWORK_PATH` before and after `resolve`, so a UNC or
  device path (`\\host`, `//host`, `\\?\`, `%5C%5Chost`) is still refused. A drive letter without a slash
  (`C:notes.md`) still matches the scheme pattern and is refused. On Linux, `C:/x` resolves under the
  document's folder, a harmless local path.
- `\??\UNC\host\…` (an NT path) decoded from `%5C??%5C…` passes `NETWORK_PATH`, but `path.win32.resolve`
  roots it on the current drive (`C:\??\UNC\…`), so it never reaches the network.
- `resolveAppAsset` (`protocol/app-assets.ts:19`) refuses `\` and checks containment with `path.sep`, so a
  drive path in a `galeo://app/` URL resolves outside `root` and is refused on Windows.
- **Proof**: `urls.test.ts`, `tests/unit/core/windows-links.test.ts`, `links.spec`, `images.spec` passed.

### SR-05 Never execute files — **PASS with L2**

- `canOpenWithDefaultApp` (`core/links/open-with.ts:21`) is still checked when the menu is built and again
  when the choice comes back (`documents/menus.ts:41-47`), on the tab's own path and its `realpath`.
- On Windows, `executable` is always false (`adapters/file-system.ts:43`), so the name list is the whole
  check there. See L2.
- macOS bundles (`.app`, `.workflow`, `.prefPane`) are folders, which `kind !== 'file'` already refuses.

### SR-06/SR-07 Zero network — **PASS**

- `network-guard.ts`, `network-policy.ts` and the CSP are unchanged. Drive paths reach only the local file
  system (SR-04 above); a drive mapped to a network share is the same case as a network mount under `/` on
  Linux, which the threat model already leaves to the user.
- No new code opens a socket. The no-network suite passed.

### SR-08 Hardened binary — **PASS**

- `packaging/after-pack.mjs` sets the same `FUSES` for every target and renews the ad-hoc signature on macOS
  after flipping them. `verify-package.mjs` checks the fuses in the packaged binary on each system
  (`win-arm64-unpacked` on Windows arm64), the macOS document types (never the default), `gal` in macOS
  Resources, and on Windows CI the registered "Open with" command `"<galeo.exe>" -- "%1"`, never the
  default, and gone after uninstall.
- The test hooks stay behind `app.isPackaged`, as before.

### SR-09 Engine update policy — **PASS**

- `electron: 45.2.1`, which is npm `latest` (2026-10-31T01:03Z). 45 is the current stable line.

### SR-10 Supply chain — **PASS with I2**

- No new runtime dependency. katex and Electron were bumped by hand, one commit each.
- **Workflows.** Every action is pinned by SHA. `platforms.yml` holds `contents: read` and `actions: read`
  only; inputs reach shell steps through `env:` (`GREP`, `SHARD`, `OS`, `RERUN`), never inline. Called by the
  release, it builds with no npm cache, so a poisoned cache can't reach a release package.
- **Release.** The tag check now runs first, on its own. `collect` runs only when the Linux build and every
  Platforms job passed, requires exactly 10 packages, and writes `SHA256SUMS`; `attest` and `release`
  re-check the sums and attest all 10. The macOS and Windows package jobs run dependency install scripts with
  a read-only token, as the Linux build job does.
- `npm audit --omit=dev` is clean; with dev dependencies it reports one moderate advisory (I2).
- Sensitive dependencies have one copy each (table below).

### SR-11 Minimal, validated IPC — **PASS (unchanged)**

- No channel or schema was added. `api.test.ts` changes only for `commandLauncher`.

### SR-12 Capability-scoped file access — **PASS**

- **Launcher, macOS and Windows.** Both channels spend a credit before anything else
  (`app/handlers.ts:91`, `:110`). The path is main's own: `~/.local/bin/galeo`, or `galeo.cmd` under an
  absolute `LOCALAPPDATA`. `installAppCommand` refuses to replace a file without galeo's mark;
  `uninstallAppCommand` removes only a marked file, with `removeFile` (one file or link, never a folder,
  `EISDIR` now reported on macOS and Windows too). The macOS command refuses a disk-image or translocated
  path. The Windows content quotes the exe, refuses a `"` in it and doubles `%`, the one character cmd
  expands inside quotes. See I1 for where the exe path comes from.
- **Opening a file whose case differs.** `spelledAsOpen` (`core/routing/open-files.ts:15`) reuses a tab's
  path only when both `stat`s give the same `dev:ino`, so on a case-sensitive disk two files stay apart. It
  stats only paths main was already opening and the window's own tabs. `openInWindow` re-checks that the
  window still has a profile after the await.
- **Find in all tabs.** Unchanged scope (the sender's tabs, kept text only for its window). The read's buffer
  is a fresh `Uint8Array` (`file-system.ts:59`), never Node's shared pool, so the transfer hands the worker
  that file's bytes and nothing else; main keeps none.
- **Proof**: `app-handlers.test.ts` (Windows and macOS install/uninstall, `launcherTarget`),
  `launcher.test.ts`, `open-files.test.ts`, `find-all.test.ts` (transfer of the read's own buffer),
  `task-runner.test.ts`, `capabilities.spec`, `find-all.spec`: all passed.

### SR-13 Arguments are data — **PASS on Linux and macOS; L1 on Windows**

- macOS: `open-file` delivers `['--', path]`; the `galeo` command is `gal`, which refuses unknown options and
  puts files after `--` (`bin/gal`).
- Windows, Explorer: `-- "%1"` in both registered commands, checked in CI. Explorer passes a full path, which
  starts with a drive letter, never `-`.
- Windows, `galeo.cmd`: see L1.
- `parseArgv` (`core/argv.ts:33`) still refuses an unknown option or a switch after a file name, after
  Chromium has read it.

### SR-14 Bounded work — **PASS**

- **Find in all tabs.** Decoding moved into the worker (`findInBytesTask`, `find-all.ts:222`), so the 5 s
  budget now covers decode and match, and main's thread never decodes a file for it. That closes v0.4 I2.
  The L1 fix holds: one read in flight per window, and the read's buffer leaves main on transfer.
  `findInBytesTask` validates its input. The task runner starts the budget before `postMessage`, so a
  failed post still ends in a timeout, not a stuck queue.
- **Quick open.** `reachesName` is one linear pass per path, before the existing matcher.
- **Renames on Windows.** At most 20 tries, 10 ms apart, only for `EPERM`/`EBUSY` on `win32`.

### SR-15 Safe saves — **PASS**

- `writeFileAtomic` and the save path change only in `renameOver`, which retries the same rename. The temp
  file, fsync and directory sync are unchanged; any other error still removes the temp file.

### SR-16/SR-17 Metadata and configuration — **PASS**

- `profileIdFor` never picks a Windows device name (`con`, `prn`, `aux`, `nul`, `com1-9`, `lpt1-9`) for a new
  profile. `isProfileId` still accepts one read from disk (for example a profile made before 0.5 and moved to
  Windows); that is the user's own data, and it can only fail to open.

## Findings

### L1 — Low — `galeo.cmd` passes file names where Chromium reads switches

- **Location**:
  - `src/core/desktop/launcher.ts:73-76` `appCommand`, win32: the command is `"<exe>" %*`.
  - `docs/security/threat-model.md:382-385` (SR-13): "Windows shells don't expand wildcards for a program, so
    a hostile file name reaches argv only if the user types it (A7 needs a glob)."
- **Vulnerability**:
  - On Linux and macOS, the `galeo` command is `gal`: it refuses unknown options and puts every file after
    `--`, so no file name reaches Chromium as a switch. `galeo.cmd` does neither; it hands every argument to
    `galeo.exe` as typed, before any `--`.
  - cmd and PowerShell don't expand wildcards on Windows, as the threat model says. But Git Bash, MSYS2 and
    Cygwin do, and they are common among the developers galeo is for. From those shells, `galeo.cmd *.md` or
    `cmd //c galeo *.md` expands the glob before cmd runs.
  - Chromium acts on switches anywhere before `--` at process start. `parseArgv` then refuses to start, but
    after the fact, as SR-13 already notes.
- **Exploit scenario** (A7 on Windows):
  1. A hostile repository holds a PE file named `--browser-subprocess-path=x.exe.md`. Windows file names
     may hold `-`, `=` and `.`, and `CreateProcess` runs a PE whatever its extension.
  2. The user clones it and, in Git Bash, runs `galeo.cmd *.md` to read the docs.
  3. Chromium starts its child processes from that file, in the folder the user is in: code execution as the
     user. (`--gpu-launcher`, the A7 example, is a POSIX wrapper; `--browser-subprocess-path` works on
     Windows.)

  It needs a globbing shell, the `.cmd` name or `cmd //c` typed by the user, and a hostile folder. Low.
- **Remediation** (either):
  1. Make `galeo.cmd` do what `gal` does: read galeo's own flags (`--new-window`, `--no-sandbox`,
     `--profile NAME`/`--profile=NAME`), refuse any other argument that starts with `-`, and pass the rest
     after `--`. A batch loop over `%1` with `shift` can do it; a unit test can drive it through
     `cmd /c` on the Windows runner.
  2. Or keep `%*` and narrow the threat model's sentence: name the globbing shells, and say a file name can
     reach Chromium as a switch from them, as on Linux without `gal`.

### L2 — Low — SR-05's list misses Windows and macOS types that run or reach the network when opened

- **Location**: `src/core/links/open-with.ts:6-14` (`LAUNCHERS`), `src/main/adapters/file-system.ts:43`
  (`executable` is always false on `win32`), `src/core/documents/menus.ts:38-47`.
- **Vulnerability**:
  - SR-05 now promises not to offer "Open with default app" for "what Windows runs or installs when it is
    opened" and "what macOS does". On Windows there is no executable bit, so the name list is the only check.
  - Missing, Windows: `.chm` (HTML Help runs its own script), `.application` (ClickOnce), `.appinstaller`,
    `.msix`, `.msixbundle`, `.appx`, `.appxbundle`, `.msp` (installer patches), `.iso`, `.img`, `.vhd`,
    `.vhdx` (mounted, and their content loses the downloaded-file mark), `.rdp` (connects to a remote host,
    and can share drives), `.theme`, `.themepack`, `.deskthemepack` (fetch from a remote path; ThemeBleed),
    `.scf`, `.library-ms`, `.search-ms`, `.searchconnector-ms` (can point at a remote share, leaking the
    user's NTLM hash), `.settingcontent-ms`, `.diagcab`, `.wsc`, `.sct` (scriptlets).
  - Missing, macOS: `.fileloc` (opens the file it points to, script included), `.inetloc` (opens any URL,
    `smb://` included), `.mobileconfig` (installs a profile after a prompt), `.iso`.
- **Exploit scenario**:
  1. A hostile repository's README links `[Full manual](docs/manual.chm)`. A clone carries no
     downloaded-file mark, so Windows doesn't warn.
  2. The user opens the link; galeo opens it as a tab and shows it as binary.
  3. The user right-clicks the document and picks "Open with default app", which galeo enables because
     `.chm` isn't listed and Windows reports no executable bit. `hh.exe` runs the manual's script: code
     execution as the user.

  It needs the user's own choice in galeo's native menu, for a file galeo couldn't show. Low.
- **Remediation**:
  1. Add the types above to `LAUNCHERS`, with an `open-with.test.ts` case per group.
  2. Consider, on Windows and macOS, offering "Open with default app" only for a list of known document types
     (images, PDF, office documents, the formats galeo reads), since no executable bit backs the list there.
     That changes how SR-05 decides, so it would need an ADR (Open questions).

### I1 — Info — The Windows command trusts an inherited `PORTABLE_EXECUTABLE_FILE`

- `launcherTarget` (`src/main/app/handlers.ts:31-33`) points `galeo.cmd` at `PORTABLE_EXECUTABLE_FILE`
  whenever it is set and absolute, whatever build is running.
- electron-builder's portable launcher sets it for its own app, and child processes inherit it. An installed
  galeo started from another portable app (a portable terminal, say) sees that app's path, and "Install
  command-line launcher" then writes a `galeo` command that runs the other app.
- No attacker controls it (same-user environment), so this is correctness more than security.
- Optional: trust it only when `process.execPath` is under the system temp folder (where the portable build
  unpacks), or when `PORTABLE_EXECUTABLE_APP_FILENAME` is galeo's.

### I2 — Info — npm audit: 15 moderate, all one minimatch advisory under electron-builder

- GHSA-g3hv-75wg-m249 (minimatch `< 11.0.1`, denial of service through glob-part amplification), published
  2026-10-30. The 15 entries are its dependents in `electron-builder` 26.18.0 (the latest), through
  `@electron/asar`, `@electron/universal`, `dir-compare`, `glob`, `filelist`/`jake`/`ejs` and
  `electron-winstaller`. Only 11.x is patched; the tree holds 3.1.5, 5.1.9, 9.0.9 and 10.2.6.
- Not reachable: these run at build time, on galeo's own patterns and file tree. Nothing ships in the app
  (`npm audit --omit=dev` is clean). The release job's audit gates on high, so it passes.
- Optional: wait for electron-builder to move to minimatch 11; an `overrides` entry across three majors
  would risk the build for no reachable gain.

### I3 — Info — `shownPath` reads `\` as a separator on Linux and macOS

- `shownPath` (`src/shared/paths.ts:29`) now treats `${home}\` as under the home folder on every system. On
  Linux or macOS, a file in `/home` named `u\notes.md` would show as `~\notes.md` for home `/home/u`.
- Making that file needs write access to `/home`, so it cannot mislead in practice.
- Optional: accept `\` only when `home` is a Windows path (it has a drive letter or holds `\`).

### Other observations (not security)

- Uninstalling galeo on Windows (NSIS) leaves `galeo.cmd` in `WindowsApps`, pointing at an exe that is gone.
  Settings' "Uninstall command-line launcher" removes it; the uninstaller could too, while it carries the
  mark.
- `platforms.yml`'s `rerun_of` downloads `last-run-*` artifacts from any run id the maintainer gives,
  including a fork's pull-request run. They are read as JSON lists of test ids only (`merge-last-runs.mjs`),
  so nothing runs from them.
