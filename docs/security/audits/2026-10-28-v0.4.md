## Attack surface map (delta since v0.3.0)

- **B3, IPC.** Four new request channels, each with a zod tuple schema in `src/shared/contracts/schemas.ts`. All
  go through the unchanged `registerIpc` sender check (`src/main/ipc/register.ts`, `handle.ts`).
  - `app.uninstallLauncher []`.
  - `documents.findAll [query ≤ 1024 chars, { caseSensitive }]` (strict object).
  - `tabs.search [query ≤ 1024 chars]`.
  - `tabs.reopenClosedTab [documentId]`.
  - `settings.set` gains `tabsPosition: 'top' | 'left'` and `tabPanelWidth: 140–480`.
  - `tabs.windows` now answers only on real input.
- **B3, a value besides methods.** `window.galeo.app.startInfo` (name, version, platform, sandbox state, cause,
  AppImage). Main puts it on the renderer's command line as `--galeo-start-info=<JSON>`
  (`window/policy.ts:49`, `shared/start-info.ts`), and the preload reads it from `process.argv`. All values
  are main's own constants or enums.
- **B3, data to the page.** Each file tab in a snapshot now carries its format and its folder as `~/…`
  (`core/tabs/page.ts`). The page already had the tab's full path. Quick open's results gain `fill`, the
  shown path, which the entry's name and folder already gave.
- **B4, reads.** Find in all tabs reads every open tab's file in main, under the 256 MB read cap, and decodes
  it there. It reads no path the window doesn't already show.
- **B4, deletes (new).** *Uninstall command-line launcher* (AppImage only) removes up to four files in the
  user's own folders: `~/.local/bin/galeo`, `<data>/applications/galeo.desktop`, the hicolor icon and
  `<data>/mime/packages/galeo.xml`, then runs `update-mime-database` as install does.
- **B5, document content.** Two new readers on the page: log line colours (`log-parts.ts`) and JSON value
  colours (`json-tree-model.ts` `parts()`), both drawn as text. Snippets from find in all tabs are drawn as
  React text.
- **Main's composition root.** The settings, profile, session, app and window channels moved into handler
  groups (`src/main/{settings,profiles,session,app,window}/handlers.ts`), with no change in what they check.
- **B8.** Electron 45.0.0; electron-builder 26.18.0; `@codemirror/view` 6.43.15 and `@codemirror/merge`
  6.12.3; dev-only bumps. No new runtime dependency.

- **Tab search.** `tabs.search` lists only the sender's own open tabs (not the settings tab) and its own closed

  threat model says.
- **Reopen by id.** `tabs.reopenClosedTab` (`handlers.ts:155`) checks that the id is in the sender's closed

  `tabs.reopenClosed`.
- **Find in all tabs.** `TabSearches.search` (`core/documents/find-all.ts`) iterates

- **Other windows.** `tabs.windows` now spends a credit (`handlers.ts:201`, `e77aaaf`), which closes v0.3 I4.

  `uninstallLauncher` removes the command, the entry and the MIME file only when they carry galeo's mark, and
  the icon only when its bytes equal the bundled one. A directory at any of those paths fails the read and
  is kept. A symlink there is removed itself, never its target (`rm` doesn't follow). See I3.

  - `find-all.spec`, `tab-search.spec`, `tab-overview.spec`, `capabilities.spec`;

## Findings

### L1 — Low — Overlapping find-in-all-tabs requests each read a whole file in main

- **Location**:
  - `src/core/documents/find-all.ts:29-50` `search()`: it raises the window's search number, then for each tab
    `await this.textOf(…)`, and checks `superseded()` only after that.
  - `find-all.ts:58-71` `textOf()`: `fs.readFile(path, { maxBytes: READ_MAX_BYTES })`, then `decodeText`.
  - `src/main/documents/handlers.ts:128`: the handler calls `searches.search` directly. No input credit, by
    design (ADR-024 point 6).
- **Vulnerability**:
  - Each call starts its own read of the first tab before anything stops it. `readFile` allocates a buffer the
    size of the file (up to 256 MB) as soon as it has the `stat`.
  - A newer query only makes the older call return *superseded* once its read and decode finish. So
    overlapping calls run their reads side by side, each with its own buffer and decoded string.
  - `documents.read` shares concurrent reads of one document (`reading`, `handlers.ts:67`, "so repeated
    requests can't multiply it"). Find in all tabs has no such guard.
  - ADR-024 point 6 says "one live search per window", and SR-14 "A newer query from the window stops the older
    search before its next tab". Both hold for the worker, not for the reads.
- **Exploit scenario**: this needs T1 in one window, plus one large file among that window's tabs. The reader
  opened, say, a 200 MB log; any file in the window works.
  1. The page calls `galeo.documents.findAll('ab', { caseSensitive: false })` 100 times without awaiting.
  2. Main starts 100 reads of the same file, allocating 100 × 200 MB outside V8's heap, plus each decoded string.
  3. The machine swaps, or the OOM killer ends main. Every galeo window goes, with the unsaved text main keeps
     for crash recovery (SR-16). Session restore doesn't bring the attack back on its own (it needs the page
     compromise again).

  The gain is a denial of service of the whole app and the loss of unsaved text in other windows. The reader
  sees it happen. Low.
- **Evidence**: a throwaway Vitest probe built `TabSearches` with the real `NodeFileSystem`, a window of two tabs
  on one 64 MiB text file, and a task runner that answers at once. It then sent 20 searches without awaiting.

  | Calls | Reads started | Reads in flight at once | Peak `arrayBuffers` growth | Answers |
  |---|---|---|---|---|
  | 20 | 21 | 20 | 1,280 MiB | 19 *superseded*, 1 *done* |

  Scaled to a 256 MB tab, 20 calls hold about 5 GiB, and 100 about 25 GiB.
- **Remediation** (any one closes it; the first is the smallest):
  1. Serialize searches per window: keep the window's running search as a promise, and have a new one await it
     (it will answer *superseded* right after its current step) before reading. Then at most one read per
     window is ever in flight, which is what ADR-024 already says.
  2. Or check `superseded()` before each read too, and share reads of one `(id, path, encoding)` as
     `documents.read` does.
  3. Add a unit test: N searches sent at once from one window cause at most one `readFile` in flight, and
     the last one answers *done*.

  This doesn't change the ADR's decision, so it needs no new ADR; SR-14's sentence is then true as written.

### I1 — Info — Electron 45.1.0 was published yesterday, and galeo is on 45.0.0

  fix for malformed asar archives whose sizes don't match the file, and a fix for a main-process crash in

### I2 — Info — Find in all tabs decodes each file on main's thread, outside its budget

- `textOf` reads and decodes the tab's file in main (`decodeText`, a `TextDecoder` over up to 256 MB), then the
  task runner copies the string to the worker. Only the match runs under the 5 s budget.
- So each search costs main a pass over every tab's bytes, on its own thread: for a window of large logs,
  hundreds of milliseconds of stall per tab, on every debounced keystroke (150 ms) in the overlay.
- `documents.read` decodes on main's thread too, so this is not a new kind of work. But ADR-024 rejected "match
  in main's own thread" for the same reason, and find in all tabs repeats the decode on every query, not once
  per read.
- Optional: decode in the worker (send the bytes, transferred, with the chosen encoding), or skip tabs over a
  size (say 50 MB) with the *too large* reason.

### I3 — Info — The launcher uninstall removes with a recursive `rm`

- `NodeFileSystem.remove` is `rm(path, { recursive: true, force: true })` (`file-system.ts:119`).
  `uninstallLauncher` uses it on paths it has just checked are galeo's files.
- Between the check and the removal, a same-user process could swap the file for a folder, and the removal
  would empty it. Same-user processes are out of scope as attackers, so this is not a defect.
- Optional: give the port an `unlink` for files and use it here, so the removal can only ever remove a file
  or a link.

### I4 — Info — `tabs.reopenClosed` needs no input, while `tabs.reopenClosedTab` spends a credit

- `tabs.reopenClosed` (`handlers.ts:139`, Ctrl+Shift+T from the palette) reopens the window's last closed tab, or
  a whole closed window of its profile, with no input credit, as it did in v0.3.
- Both reopen only what the profile had, so neither reaches a new file. But a compromised page can reopen all
  25 closed tabs and every closed window in a loop, without input, while `reopenClosedTab`, which reaches the
  same tabs, spends a credit.
- Optional: spend a credit there too, for one rule across the reopen channels.
