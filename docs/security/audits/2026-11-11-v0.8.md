# galeo v0.8 pre-release security audit, 2026-11-11

- **Commit reviewed**: `2a62332` (main). Delta `v0.7.0..2a62332`: 40 commits, 71 files under `src/`, plus packaging,
  scripts and workflows. The working tree's uncommitted Electron 45.3.0 bump (`package.json`, lock, `dependencies.md`)
  is noted under I2.
- **Scope**: incremental reads (`documents.read(id, held)`, ADR-033); watching a folder (`watch.*`, `watch.changed`,
  `--watch DIR`, session version 3, ADR-034); main reading an SVG's bytes for its size (`documents.resolveImage`, #44);
  a profile launcher renamed with its profile (#38); `window.pageFailed`; the Windows uninstall deleting `galeo.cmd`
  (#47); the `.deb` after-remove deleting the apt key on purge only; `apt-repo.sh` multi-arch and `pages.yml`; the
  release workflow's arm64 job (ADR-035); split-view scroll sync; the launcher's stderr pass-through; `npm audit`;
  Electron currency (SR-09).
- **Result**: 0 Critical, 0 High, 0 Medium, 1 Low, 5 Info. Status after the fixes in the table below: L1, I2, I4, I5 fixed; I1, I3 accepted.

| Low | 1 | L1 `svgSize` (`src/core/documents/svg-size.ts:19`) runs `/([\w:.-]+)\s*=\s*("[^"]*"\|'[^']*')/g` over the root `<svg …>` start tag, up to 16 KiB. A tag with a long run of name characters and no `=` makes the engine retry the greedy run at each start position: O(n²). Measured with the real function on Node 24: an `<svg aaaa…a>` of 16 300 bytes takes **639 ms**, 8 000 bytes 212 ms; a normal tag 0 ms. It runs in main (`DocumentLinks.svgSizeOf`, `src/core/documents/links.ts:139`) for every `documents.resolveImage` of an SVG ≤ 1 MiB, with no cache: the page asks once per `<img data-galeo-src>` (`src/renderer/document/DocumentView.tsx:398`), and again on every live reload. Exploit: a downloaded repository (the untrusted-bundle case of the threat model) carries `README.md` with 100 `![](logo.svg)` and a crafted `logo.svg`; opening it stalls main's event loop for about 60 s, so every window stops answering (IPC, menus, saves, closing). The tab is restored with the session, so the next start stalls again. Availability only, needs the crafted file next to the document, hence Low; it breaks SR-14 (bounded work). Fix: start a match only at a name boundary, `/(?<![\w:.-])([\w:.-]+)\s*=\s*("[^"]*"\|'[^']*')/g` (measured 0 ms on the same inputs, same matches on normal tags), or a hand-written attribute scanner; a unit test with a 16 KiB tag under a time bound; optionally cache the size by grant (path + identity) |
| Info | 5 | I1 `npm audit`: 6 moderate, all minimatch GHSA-g3hv-75wg-m249 under electron-builder 26.18.0, as in v0.7; `npm audit --omit=dev` finds 0. I2 HEAD's `package.json` pins Electron 45.2.3; npm's `latest` is 45.3.0 (published 2026-11-10), already bumped in the uncommitted working tree with `docs/dependencies.md`. SR-09 holds once that is committed (and CI/e2e run on it) before the tag. I3 `FolderWatch.watchFolder` (`src/core/watch/folder.ts:178`) watches up to 1 000 folders and **polls every folder past that, without a cap**; each 3 s tick lists and `stat`s every entry of every polled folder, one after another (`tick`, `poll`). The first walk is bounded (50 000 files, 3 s), but `arrivedFolder` walks each new folder with its own budget and adds its subfolders. An agent (or a build, `node_modules` under a name not in the skip list) creating 50 000 folders in the watched folder leaves main doing a continuous scan of all of them for as long as the watch lasts. The reader chose the folder and can stop the watch; no content is read. Suggest a cap on polled folders (e.g. 1 000, then a "partly watched" status). I4 `FolderWatch.list` checks the entry's real path is inside the folder when it lists it, but `watch.open` opens the listed path later (`FolderWatches.choose` → `open`), without a re-check. Whoever writes into the folder (the agent ADR-034 is for) can list `notes.md`, then replace it with a symlink to `~/.ssh/config.md` (any file with a known type) before the reader clicks: galeo opens a file outside the folder. It shows only in the reader's own window, galeo sends nothing out (SR-04), and a hard link would do the same without a symlink, so no exfiltration; but it breaks "an entry whose real path leaves the folder is never opened" in spirit. Two edge cases of `inside()` (`folder.ts:290`): a watched root of `/` or `C:\` lists nothing (the prefix becomes `//`, fails closed), and on POSIX `\` counts as a separator, so a sibling folder named `<root>\x` passes. Suggest: re-check the real path in `choose` before opening, and compare with the root's own separator. I5 `watch.openAllNew` spends one credit and opens every not-yet-opened entry, up to 200, without `confirmBurst`. A compromised page needs one real input to open them; they are files of the granted folder only, opened hibernated but the shown one. By design (the panel's button); noted for SR-12's credit rule |

## Attack surface delta (since v0.7.0)

| Entry point | Trust boundary | Controls verified |
|---|---|---|
| `documents.read(id, held)` | renderer → main; reads a file | zod: `documentId`, `version.nullable()`; the id looked up in the sender's window, Settings refused; reads serialised per tab and file (`lastRead`), shared per key. An append is sent only when the page's `held` equals main's own copy's version, the file is at least as long, `samePrefix` compares the old bytes exactly (`Buffer.equals`), the view and banner don't change, and the tail decodes alone (UTF-8 fatal, UTF-16 on a code unit, Windows-1252; never a guessed encoding, UTF-32 or after U+FFFD) (`src/core/documents/incremental.ts`, `read.ts`). The version is SHA-256 continued over the tail (`hash.copy().update`), equal to a full SHA-256, so save conflicts (ADR-013) are unchanged. **Articles always read in full**, so main's link and image set stays the whole text's (SR-04). Copies: files ≥ 1 MiB, ≤ 512 MiB in all, LRU, keyed by tab and path + encoding, forgotten with the tab and on crash reload. A page that lies about `held` gets text it can't join and re-reads in full: it can only spoil its own view |
| `watch.choose()` | renderer → main; grants a folder | empty tuple; an input credit before main's folder dialog (`openDirectory`); the page never sends a path (`src/main/watch/handlers.ts`) |
| `watch.open(id, newWindow)`, `watch.openAllNew()` | renderer → main; opens files | an input credit each; ids from `SelectionGrants` list `watch`, replaced on each offer and cleared on stop and window close; opened through the normal open path (`openInWindow`, not `chosen`) or a new window of the sender's profile. I4, I5 |
| `watch.stop()`, `watch.state()`, `watch.panel(open)` | renderer → main | sender's own watch only; `panel` is a boolean the session keeps; no credit (they only reduce or show) |
| `watch.changed` event | main → renderer | names, folder (relative, `/`), kind, time, opened flag, opaque id; the shown folder as `~/…`. No path of an entry, no content. ≤ 4 updates a second per window (`UPDATE_MS`), ≤ 200 entries. Rendered by React as text (no HTML sink in the delta's renderer code) |
| Folder watch itself | file system → main | real path of the root; depth 4; the walker never enters symlinked folders and enters each folder once by identity; arrived folders entered only when `realpath(path) === path`; files listed only with a known type and a real path inside the root; built-in and profile skip lists; `seen` ≤ 100 000 names. Missing or denied root polled until back. I3, I4 |
| `--watch DIR` | command line / second instance → main | `readWatch` (`src/core/argv.ts`): the next argument or `=value`, never one starting with `-`, at most once, resolved against the request's cwd; before `--` only (SR-13). `bin/gal` does the same and passes it marked (`o--watch`, `o<path>`); the folder isn't a Chromium switch. A missing folder shows as missing |
| Session file v3 | disk → main | `watch: z.strictObject({ folder: absolute path ≤ 32 767, panel: boolean }).optional()`; 2 → 3 migration is the identity; restored only while `stat` says directory (`FolderWatches.restore`); the 4 MiB cap (SR-17) unchanged |
| `documents.resolveImage` (SVG size, #44) | main reads a file | only after the existing checks (in the document's image set, a file, an image type, ≤ `IMAGE_MAX_BYTES`), only `.svg` ≤ 1 MiB, only the first 16 KiB parsed as ASCII, numbers checked finite and positive; the size is a hint for the viewer (`ZoomViewer`, `offerZoom`), never markup. L1 |
| `window.pageFailed()` | renderer → main | empty tuple; recovers the sender's window through `windowCrash.recover`, which counts in `CrashRecovery` like a real crash, so the crash-loop message and "stay down" still stop a page that calls it in a loop. It drops warm tabs, read copies and clean edit grants (all reductions). A compromised page gains nothing it couldn't by crashing itself |
| Profile rename → launcher | main writes a desktop entry | `renameProfileLauncher` (`src/core/desktop/launcher.ts`): refused for a name with a control character (no newline can add a key); reads ≤ 64 KiB; only a file carrying `X-galeo-Profile=<id>`; only `Name=`/`Comment=` of `[Desktop Entry]` replaced, `\` escaped; `Exec` kept as installed. Written 0644 as the install is |
| `tabs.menu` "Close others" | native menu → page | one more `TAB_MENU_CHOICES` value; the page closes its own unpinned tabs through the existing channel |
| Windows uninstall | installer → user's files | deletes `%LOCALAPPDATA%\Microsoft\WindowsApps\galeo.cmd` only when its second line is exactly galeo's mark (`S==`, CRLF included), never during an update; generated from `scripts/lib/associations.mjs`, a test keeps the mark equal to `appCommand`'s |
| `.deb` after-remove | package scripts | the keyring `/usr/share/keyrings/galeo-archive-keyring.asc` stays on `remove`, goes on `purge` (ADR-029 pt 6). It is trusted only through the galeo sources entry's `Signed-By`, which also stays until purge, so a removed galeo leaves no key trusted for other repositories |
| `scripts/apt-repo.sh`, `pages.yml` | CI → published apt repository | each downloaded `.deb` checked against `SHA256SUMS` and `gh attestation verify`'d **one by one** (release workflow, this tag, `--deny-self-hosted-runners`); an amd64 `.deb` required, at most two; `build` refuses a package not named galeo, an architecture outside `amd64 arm64`, two for one architecture, or mixed versions, before writing anything; every `.deb` must ship the key; `check` runs `apt-get update` + download per architecture trusting only the key |
| `release.yml` arm64 job | CI | GitHub-hosted `ubuntu-24.04-arm`, `contents: read`, no secrets; the same verify, plus e2e; artifacts per arch; 12 packages counted, checksummed and attested in the later jobs as before |
| `ci.yml`, `platforms.yml` | CI | CI skipped for Dependabot's actor (its PRs never merge) and docs-only pushes (`npm run check` before commits); a Windows quit check that only reads process lists. No new `${{ }}` of untrusted input in `run:` |
| `packaging/linux/galeo.sh` | launcher | `awk -W interactive` only when that awk accepts it; no argument handling changed |

Nothing changed in the preload's shape beyond the new channels and event, in window creation, CSP, fuses or the
permission handler: SR-01, SR-02, SR-06 and SR-08 carry over. All seven new channels and `watch.changed` are in
`CHANNELS`/`EVENTS` and `requestSchemas`, so SR-11's sender and frame checks apply.

## Per-SR verification (SRs the delta touches)

- **SR-02/SR-03 content is inert — PASS.** Appended text goes into CodeMirror (`appendText`) or the host views as
  before; the watch panel is React text. The only new `innerHTML` in the delta is a test reset.
- **SR-04 no network — PASS.** Incremental reads never apply to articles, so links come from the full text; the watch
  reads no content; the SVG size is a number.
- **SR-09 engine updates — PASS once I2 is committed.** 45.3.0 is `latest` on npm (checked 2026-11-11).
- **SR-10 supply chain — PASS with I1.** No new package: vitest 5.0.5 → 5.1.0 (dev), mermaid 12.3.0 tried and reverted
  to 12.2.0, Electron 45.3.0 pending.
- **SR-11 minimal, validated IPC — PASS.** Seven channels, each zod-validated, scoped to the sender's window.
- **SR-12 capability-scoped file access — PASS with I4, I5.** A folder is granted only by `--watch` or main's dialog
  after real input; entries open by offered id after real input; the page never names a path.
- **SR-13 command lines — PASS.** `--watch` takes its folder as data, before `--`, in both `gal` and `parseArgv`.
- **SR-14 bounded work — FAIL before the L1 fix.** L1 (unbounded main-thread time per image request); I3 (polled
  folders unbounded). The incremental copies are bounded (512 MiB, accepted in ADR-033).
- **SR-17 local metadata files — PASS.** Session v3 is a strict, bounded addition, the folder re-checked on restore.
- **Packaging and release (ADR-029, ADR-035) — PASS.** Per-architecture attestation and checksum before signing; the
  kept key is scoped by `Signed-By`.
