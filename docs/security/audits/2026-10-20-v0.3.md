# galeo v0.3 pre-release security audit, 2026-10-20

> Security requirements (SR-xx) and threats (Tn) are defined in the [threat model](../threat-model.md).
> File and line references point into the audited commit, and "Status after fixes" records what became of
> each finding.

- **Commit audited**: `22fd100` (main, clean tree). The delta is `v0.2.0..22fd100`: 74 commits, 188 files
  (127 under `src/`).
- **Scope**:
  - the font list: `settings.fonts` and its `fc-list` child process;
  - moving tabs between windows: `tabs.dragStart`, `dragEnd`, `adopt`, `moveTo`, `windows`, `TabDrags`,
    `tabMover`, and `documents.recover`'s new `edit` flag;
  - the render worker's JSON and CSV/TSV readers, and the tree and table views that draw them;
  - table options and *Show as table* (`tabViewState.table`, the `tableSeparator`/`tableHeader` settings);
  - lazy grammars from `@codemirror/language-data`;
  - the hardening since v0.2: the save's byte cap, the leftover temp-file sweep, the diagram style-sheet URL filter,
    the MDX MIME type and its `update-mime-database` child process, and the task runner's start budget.

  Controls that the delta does not touch carry over from the [v0.2 audit](2026-10-10-v0.2.md) and are not
  re-audited here.
- **Method**: I read the code for each control and ran the suites that prove them. Three findings needed a live
  check. For two of them I wrote throwaway Playwright probes, ran them headless, and then deleted them. The third
  was a Node `execFile` probe in a scratch folder, also deleted. The tree is clean again.

## Attack surface map (delta since v0.2.0)

- **B3, IPC.** New request channels, each with a zod tuple schema in `src/shared/contracts/schemas.ts`. All go
  through the unchanged `registerIpc` sender check.
  - `tabs.width [id, 40–200 | 'full' | null]` and `tabs.viewState` gain `table {separator, header, asTable}`.
  - `tabs.dragStart [id]`, `tabs.dragEnd [id, outside]`, `tabs.adopt [id, position]`,
    `tabs.moveTo [id, window | 'new']` and `tabs.windows []` (ADR-019).
  - `settings.fonts []`.
  - `settings.set` gains `tableSeparator`, `tableHeader`, and `measure: 'full'`.
  - `documents.recover` now answers `{ edit, kept }`.
  - New main→page event: `tabs.dragging` (a boolean, sent to every window).
- **B3, cross-window.** Pages can now move tab records, with their edit grant and unsaved text, between windows
  and profiles. Main holds one pending drag (`src/core/tabs/drags.ts`), and the drag data carries the tab id
  (`application/x-galeo-tab`, `TabBar.tsx:219`).
- **B4/B1, child processes (new).** Main runs two programs:
  - `fc-list -f '%{family[0]}\t%{spacing}\n'` on the first `settings.fonts` request (`font-catalog.ts`);
  - `update-mime-database <XDG_DATA_HOME>/mime` after *Install command-line launcher* on the AppImage
    (`index.ts:801`).

  Both go through `runFile` (`run-file.ts`): `execFile`, no shell, fixed arguments.
- **B4, writes.** `saveDocument` refuses text that encodes to more than 256 MB. Every atomic write now sweeps
  `.<name>.<uuid>.tmp` leftovers older than an hour. The AppImage launcher writes `~/.local/share/mime/packages/
  galeo.xml`, and the `.deb` writes `/usr/share/mime/packages/galeo.xml` as root.
- **B5, document content.** Three new readers of untrusted text:
  - the JSON indexer (`src/shared/json-index.ts`);
  - the CSV/TSV reader (`src/shared/csv.ts`), both in the render worker;
  - the page-side tree and table views (`json-tree-view.ts`, `csv-table-view.ts`).

  Source files get grammars from `@codemirror/language-data`, chosen by main's format detection from the file
  name, never by content.
- **Desktop.** The `.desktop` entry now offers galeo for 33 MIME types, among them JSON, YAML, CSV and source
  code. A shared-mime-info package adds `text/mdx`.

## Per-SR verification (SRs the delta touches)

### SR-01 Hardened renderers — **PASS (unchanged)**

- The only change to `factory.ts` is an optional `size` for a torn-off window. `webPreferences`, navigation and
  permission handlers are untouched.
- `tests/e2e/security/` passed.

### SR-02 Content is inert (JSON, CSV, grammars) — **PASS**

- **Control**:
  - The JSON tree and the CSV table never build HTML.
    - Cells are set with `textContent` and `title` (`csv-table-view.ts:100-101,128-129`).
    - Tree rows `append` a string label (`json-tree-view.ts:80`).
    - The grid's and tree's `aria-label` is set with `setAttribute`.
  - A grep of `src/renderer` and `src/shared` finds no new `innerHTML`, `outerHTML`, `insertAdjacentHTML` or
    `dangerouslySetInnerHTML`. The only HTML sink is still `host.ts:67`, behind `galeo-document`.
  - The JSON index is typed arrays of offsets. Keys and strings are decoded with `JSON.parse` of their own slice
    only when shown (`keyOf`, `scalarText`), so `__proto__` stays data.
  - `.html`, `.htm`, `.svg`, `.xml` and `.vue` are `code`: source view only (`FORMAT_VIEWS.code`,
    `rendered: 'none'`). No new rendered format executes or embeds content, so §7's "HTML files, SVG as
    documents" revisit trigger is not hit.
  - Grammars are bundled chunks loaded with `import()` under `script-src 'self'`. `@codemirror/language-data`
    has no `fetch` and no URL. The language name comes from `CODE_LANGUAGES` by file name.
- **Proof**:
  - `json-tree.spec`, `csv-table.spec` and `highlight.spec` passed.
  - The no-network JSON/CSV payload case passed (9/9).

### SR-03 Safe rich renderers — **FAIL (style sheet) → L2**

- `9e40802` adds `fragmentUrlsOnly` over the diagram's `<style>`. It catches `url(…)` in any case, quoting or
  spacing.
- It does not catch `image-set("…")` or a CSS-escaped `url` (`u\72l(`).
- `%%{init}%%` can still set the top-level `fontFamily`, which is not in `secure`
  (`mermaid-engine.ts:21`). Mermaid checks it only for balanced braces.
- So SR-03's "every URL … in the diagram's own style sheet must point to one of the diagram's own fragments"
  doesn't hold. See L2.

### SR-04 Only safe URLs reach the OS — **PASS (unchanged)**

### SR-05 Never execute files — **PASS**

- `open-with.ts` is unchanged.
- The new MIME types make galeo a handler for `application/x-shellscript`, `text/x-python` and others. Galeo
  reads those files and never runs them.
- The `.deb`'s after-install copies `mime.xml` from `/opt/galeo/resources` (root-owned) and runs
  `update-mime-database /usr/share/mime`. after-remove reverses both.

### SR-06/SR-07 Zero network — **PASS**

- The no-network suite passed, including the font pickers under `strace -f` (which follows `fc-list`), and the
  JSON and CSV cases.
- L2's requests were blocked by the CSP (`img-src 'self' galeo: data:`) before the request guard. Both still
  hold.

### SR-09 Engine update policy — **Re-check at release → I2**

- `package.json` pins `electron: 44.9.1`.
- npm `latest` and `44-x-y` are 44.9.2, published 2026-10-20T17:44Z.

### SR-10 Supply chain — **PASS**

- `@codemirror/language-data` 6.5.2 is the one new runtime dependency. It is listed in `docs/dependencies.md`
  with its 17 `lang-*`, `legacy-modes` and 10 `@lezer/*` packages.
- A scan of the production tree finds one copy each of every `@codemirror/*` and `@lezer/*` package, of
  `dompurify` 3.4.17 and of `mermaid` 12.2.0. Duplicates are as in v0.2 (`parse5`, `entities`, same version)
  plus Mermaid's layout and `d3` internals.

### SR-11 Minimal, validated IPC — **PASS**

- Every new channel has a tuple schema and a test in `src/main/ipc/schemas.test.ts`. That covers `tabs.width`,
  the five tab-move channels, `settings.fonts` (rejects arguments) and `tabViewState.table`.
- The preload is generated from `CHANNELS`, so there is one fixed method per channel.
- `tabs.dragging` is an event only.

### SR-12 Capability-scoped file access (tab moves) — **PASS with L1**

- **Control**:
  - `tabs.dragStart` accepts only the sender's own non-settings tab, and only by spending the held mouse press or
    an input credit (`handlers.ts:145`).
  - `tabs.moveTo` spends a credit, and goes only to a window in `otherWindows`.
  - `tabMover` moves the grant before the registry, so `grants.sync` doesn't drop it, and never moves the
    settings tab.
  - `documents.recover` answers only for a grant whose window is the sender.
  - The move keeps the history entries' `chosen` flag, so ADR-015's question isn't skipped for a file the reader
    didn't hand over.
- **What fails**: `tabs.adopt` (`handlers.ts:165`) calls `drags.claim(id, now())` with no check of which window
  the drop was on. Main can't see that, which ADR-019 accepts. The only thing standing in for it is knowing the
  tab's id. A window that held the tab earlier knows it. See L1.
- **Proof**:
  - `tests/unit/main/tab-handlers.test.ts` (claim once, no drag no tab, palette on input)
  - `tests/e2e/tab-move.spec.ts`
  - Both passed.

### SR-13 Arguments are data (child processes) — **PASS with L3**

- `runFile` is `execFile` with no shell. The arguments are constants (`fc-list`) or an absolute path from main
  (`update-mime-database`, where `xdgDataHome` keeps only an absolute `XDG_DATA_HOME`). Nothing comes from the
  page.
- `parseFontList` drops empty, over-100-character and control-character names. `fontStack` blanks
  `' " \ ; { }` and controls before quoting, so a hostile installed font name can't break out of the token.
- **Gap**: the programs are found through `PATH`, including relative entries. See L3.

### SR-14 Bounded work — **FAIL → M1**

- **Worker side, PASS**:
  - Both readers are single linear passes with no regular expressions.
    - JSON: `JSON.parse` (iterative in V8) then the indexer. Capped at 200,000 nodes and 1,000 levels;
      `Uint32Array` offsets fit the 256 MB read cap.
    - CSV: capped at 1,000,000 rows kept and 10,000,000 fields.
  - The worker keeps its 2 s, 30 s (tables) and 60 s `terminate()` budgets, and Cancel replaces it.
  - The task runner's budget now starts when the worker is `online`. A worker that never starts fails after
    10 s, so the worst case is 10 s plus the budget, still bounded.
- **`fc-list`, PASS**: 5 s and 4 MB (`font-catalog.ts`).
- **Page side, FAIL**:
  - The table view virtualizes rows but not columns.
  - Every drawn row builds `table.columns` cells, padding short rows with empty ones (`csv-table-view.ts:121`).
    The header builds one per column.
  - All of this runs synchronously on the page's thread, outside every budget. See M1.

### SR-15 Safe saves — **PASS (I5 noted)**

- **Size cap**: `save.ts:38` refuses `encoded.bytes.length > maxBytes` (256 MB) before `saveFile`. This closes
  v0.2 I2's "saved but can't be read again" half. The temporary encoded buffer (up to about 1 GiB for 256 Mi
  characters) is still allocated first, which takes a grant.
- **Sweep** (`file-system.ts:240`):
  - It runs after a successful `rename` or `writeFileAtomic`, on the real path's folder.
  - It matches only `.<basename>.<uuid-v4>.tmp`.
  - It `lstat`s each match and unlinks only a regular file owned by the app's uid, with `mtime` over an hour
    old.
  - It is best effort: every error is swallowed, so a sweep can't fail the save it follows.
  - `unlink` never follows a symlink. A rival user who swaps an entry between `lstat` and `unlink` can only
    make galeo remove a name in a folder that user can already write.
- The N4 fix (`O_NOFOLLOW` + `dev:ino`, `file-system.ts:277`) is intact.
- **Proof**:
  - `file-system.test.ts` (sweep cases)
  - `save-document.test.ts` (cap)
  - `edit.spec`
  - All passed.

### SR-16 Local metadata hygiene (tab moves) — **PASS**

- A moved tab's unsaved text goes from the source page to main (`keepNow` before `dragStart`), and the
  destination reads it back with `documents.recover`.
- Nothing is written to disk: the session gains only `width`, and the strict `tabViewState.table` holds only
  enums and booleans.
- `emptiedByMove` keeps a window emptied by a move out of its profile's session.

### SR-17 Robust configuration — **PASS**

- The new settings are strict enums or booleans (`settingsOverrides`). `measure` is `40–200 | 'full'`.
- `src/main/settings/schemas.test.ts` covers both.

## Findings

### M1 — Medium — A wide CSV freezes its window: the table draws every column of every row in view, on the page's thread

- **Location**:
  - `src/renderer/document/csv-table-view.ts:95-131`: `columnHeader` per column, and `row()` loops
    `column < table.columns` for every drawn row, about 40 rows plus 10 overscan each side.
  - `src/shared/csv.ts`: there is no limit on columns, only on rows (1M) and fields (10M).
- **Vulnerability**:
  - The worker's budgets bound the parse. The page then builds `rows-in-view × columns` cells synchronously.
  - `columns` is the widest row's field count, and every other row is padded to it.
  - Each cell's full text also goes into `textContent` and `title`, with no length limit.
  - *Show as table* gives any text file the same path, and its `asTable` choice is kept in the session.
- **Exploit scenario**: a repo ships `data.csv`. Its first line is `x,` repeated 200,000 times (400 KB), followed
  by a few normal rows.
  - Opening it, from Files, a link, quick open or the command line, freezes that window with no way to switch
    tabs or close it from the page.
  - The tab is the window's shown tab, so the session restores it. Every later launch of that profile freezes
    the same way, until the reader deletes the session or starts another profile. This is abuse case A8.
  - A hang is not a crash, so the crash breadcrumb (`tabs.rendering`) never marks the tab.
  - No renderer compromise is needed.
- **Evidence**: a throwaway headless probe opened `wide.csv` (one row of N fields, then 200 rows of `1,2`) and
  timed how long the grid took to appear:

  | Columns | File size | Grid shown after | Cells built |
  |---|---|---|---|
  | 20,000 | 40 KB | 23.9 s | 840,042 |
  | 200,000 | 400 KB | not within 200 s | — |
  | 1,000,000 | 2 MB | not within 200 s | — |

- **Remediation**:
  1. Draw only the columns in view, as rows already are. Alternatively, cap the columns drawn (for example
     1,000) with a banner like `rows-capped`, and count the hidden ones in the status.
  2. Make the reader enforce it too: add `columns` to `CsvLimits`, and have `parseCsv` return `too-large` past
     it. Then neither the table nor *Show as table* can be handed an unbounded width.
  3. Cut long text in the cell and its `title` (for example 1,000 characters with an ellipsis; the source view
     has the full text). Do the same for JSON keys and number literals in `json-tree-model.ts` `label()`, which
     unlike strings aren't cut to `PREVIEW_CHARS` (not probed).
  4. Add `wide.csv` (and a CSV with one 50 MB cell) to the pathological corpus, with a time budget in
     `pathological.spec`.
  5. Defence in depth, optional: on a window's `unresponsive` event, have main mark the breadcrumb tab
     `crashed`, as it does on `render-process-gone`. Then a hang the code missed doesn't come back on restore.

### L1 — Low — A window that once held a tab can take it the next time the reader drags it, from any window

- **Location**:
  - `src/main/tabs/handlers.ts:165` `tabs.adopt` → `drags.claim(id, now())`. No `from` is passed, and nothing
    ties the claim to the drop.
  - `src/core/tabs/drags.ts:32` `claim`.
  - `src/main/tabs/transfer.ts`: a move keeps the tab's id.
- **Vulnerability**:
  - ADR-019 relies on "the destination learns the id only from a real drag". But the id never changes, so any
    window that held the tab, or read a drop of it, still knows the id.
  - Every drag of a tab, including a reorder within its own window, starts a claimable drag. It stays claimable
    for the whole drag (up to 2 min) and 500 ms after it ends. `tabs.dragging(true)` is sent to every window
    when it starts.
- **Exploit scenario**: this needs T1 in window B.
  1. The tab `notes.md` was in B and the reader moved it to window A.
  2. Later, in A, the reader puts it in edit mode, so it gains a grant and maybe unsaved text.
  3. The reader then drags it to reorder A's tabs. B's page hears `tabs.dragging(true)` and calls
     `tabs.adopt(<id>, 0)`.
  4. Main moves the tab, with its grant and unsaved text, into B.
  5. B reads it with `documents.recover`, and can save it on the reader's next key press in B.

  The gain is write access to a file the reader put in edit mode, in a window they didn't choose. The tab
  visibly jumps windows. Low.
- **Remediation**: make the claim a per-drag secret instead of the tab id.
  - `tabs.dragStart` returns a fresh random token. The page puts the token, not the tab id, in
    `application/x-galeo-tab`.
  - `tabs.adopt(token, position)` claims by token. Main maps the token to the tab.
  - Only a page that got this drag's drop data can then claim, and stores stay keyed by tab id. That avoids the
    re-keying the ADR rejected.
  - Test: an adopt naming the dragged tab's id, without the drag's token, is refused.
  - This refines ADR-019 point 1 ("the drag carries the tab id"), so by convention it is a new ADR, or an owner
    one-off.

### L2 — Low — Outside URLs still reach a diagram's style sheet, via `%%{init}%%`'s top-level `fontFamily`

- **Location**:
  - `src/renderer/document/mermaid-engine.ts:21`: `secure` doesn't include `fontFamily` or `altFontFamily`.
  - `mermaid-engine.ts:59,73`: `URL_REFERENCE` / `fragmentUrlsOnly` match only a literal `url(`.
- **Vulnerability**:
  - Mermaid's `sanitizeDirective` passes `fontFamily` through `sanitizeCss`, which only checks that braces
    balance. The value then lands in `#<id>{font-family:…}`.
  - A value with no braces adds declarations to that rule.
  - `image-set("https://…" 1x)` names a URL without `url(`, and `u\72l(…)` is `url(` after CSS unescaping.
    `fragmentUrlsOnly` catches neither.
  - The e2e inert check (`diagrams.spec.ts:251`) uses the same `url\(` pattern, so it can't see them.
- **Exploit scenario**: a Markdown diagram that starts
  `%%{init: {"fontFamily": "x;background-image:image-set(\"https://t.example/p.png\" 1x);border-image:u\\72l(https://t.example/q.png) 1"}}%%`
  gets both URLs into the shadow root's style sheet. This is a tracking pixel attempt (T3, A3).
- **Evidence**: a throwaway headless probe rendered that diagram.
  - The style text read `#galeo-diagram-1{font-family:x;background-image:image-set("https://example.com/a.png" 1x);border-image:u\72l(https:…`.
  - Chromium tried both URLs, and the CSP refused both (`img-src 'self' galeo: data:`).
  - No connection was made, and the request guard and host-resolver rules are still behind the CSP. The
    impact is a failed control layer, not a leak.
- **Remediation**:
  1. Add `fontFamily` and `altFontFamily` to `secure`. The app's theme sets the diagram's font, and a document
     doesn't need to.
  2. Harden `fragmentUrlsOnly`:
     - remove any `\` from the style text (Mermaid's own CSS has none);
     - neutralise `image-set(`, `-webkit-image-set(`, `cross-fade(`, `image(` and `@import`;
     - or, simpler, drop any declaration whose value has `:` or `/` after `url(#`.
  3. Add the payload above to `mermaid.payloads.md`, and widen the inert check's pattern to
     `image-set|\\|@import`.

### L3 — Low — `fc-list` and `update-mime-database` are found through `PATH`, so a relative entry runs a planted program

- **Location**:
  - `src/main/adapters/run-file.ts:8` (`execFile(file, …)` with a bare name and the inherited `PATH` and
    working folder);
  - `font-catalog.ts` (`'fc-list'`);
  - `index.ts:801` (`'update-mime-database'`).
- **Vulnerability**:
  - Main keeps the working folder it was started in. That's the terminal's folder for `galeo`/`gal` (`launch.cwd`).
  - A `PATH` with `.` or an empty entry ahead of `/usr/bin` makes `execFile('fc-list')` run `./fc-list`
    from that folder.
  - git keeps the executable bit, so a cloned repo can ship one.
- **Exploit scenario**: the user's `PATH` is `.:/usr/bin:…` or starts with `:`. They run `galeo README.md`
  inside a cloned hostile repo that contains an executable `fc-list`. Opening Settings → the font picker runs it
  as the user. The same happens on the AppImage for *Install command-line launcher* with
  `update-mime-database`.
- **Evidence**: in a scratch folder holding an executable `fc-list` that prints a marker, `execFile('fc-list', …)`
  from Node 24:
  - with `PATH=.:/usr/bin:/bin`, it ran the planted file;
  - with `PATH=:/usr/bin:/bin`, it ran the planted file;
  - with `PATH=/usr/bin:/bin` or `/usr/bin:/bin:`, it ran the system `fc-list`.
- **Why Low**: such a `PATH` already exposes the user's shell to the same file. But galeo's promise is that
  opening a file runs nothing (T2, SR-05), and the font picker isn't where a reader expects that risk.
- **Remediation**: in `runFile`, pass `env: { ...process.env, PATH: <only absolute PATH entries> }`, or
  resolve the program to an absolute path from those entries before calling `execFile`. Setting `cwd: '/'`
  also works (libuv changes folder before its `PATH` search), but filtering states the intent. Add an adapter
  test with a fake `PATH` holding `.` and `''`.

### I3 — Info — A failed font list runs `fc-list` again on every request, from any page, with no input

- `FcListFontCatalog.list` sets `listed = null` on failure (`font-catalog.ts:22`).
- `fc-list` might be missing, time out (5 s) or overflow (4 MB). A compromised page calling `settings.fonts` in
  a loop then starts a process each time: immediately when it's missing, or one every 5 s when it hangs.
- The threat model's "it runs once" holds only for a successful list.
- No impact beyond process churn. Optional: keep a failure for a minute, or for the window's life.

### I4 — Info — `tabs.windows` tells any page, without input, which file and profile every other window shows

- `otherWindows` (`index.ts:585`) returns every other window's profile name, accent and shown file's base name,
  across profiles. That is the palette's *Move tab to window…* list.
- It is Internal-class metadata, and a compromised page has no way out with it (SR-04, SR-06).
- Profiles aren't a security boundary in the model. Noted, so that one isn't assumed.

### I5 — Info — The temp sweep deletes a crashed save's text an hour later, without saying so

- When main dies between writing the temp file and the `rename`, the temp may be the only copy of what the
  reader saved. Main's in-memory kept text dies with it.
- The next save of that file, an hour or more later, removes the temp silently.
- This is the behaviour SR-15 chose, so it is not a defect. Consider one line in USAGE ("a crash mid-save
  leaves `.<name>.<id>.tmp`; galeo removes it after an hour").

## Questions raised, and what was decided

1. **M1 severity and shape.** Medium accepted. The table now draws only the columns in view; a new reader limit
   of 10,000 columns is recorded in SR-14 and here, while ADR-018 stays the record of its own limits.
2. **L1 fix.** A new ADR, [ADR-022](../../decisions/ADR-022-drag-tokens.md), which supersedes ADR-019's point 1
   and the claim in its point 3. A first version had main make the token; drag data can only be set inside
   `dragstart`, before main could answer, so the source page makes it and registers it with main.
3. **L2.** Documents no longer set the diagram fonts (`fontFamily` and `altFontFamily` are secure keys), and the
   style filter was tightened as well.
4. **I2.** Electron 44.9.2 was taken before tagging (its release notes are empty).
5. **Not audited** (out of scope or not reachable statically):
   - X11 drag behaviour (ADR-019 notes it as unverified);
